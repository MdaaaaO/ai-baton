The response treats this as decomposing an existing epic: it plans (or says it will plan, once it has read the epic) child tickets, each with a Sizing line, `## Done when` ids and an area of repo paths, grouped into waves by their dependencies, and an owner go on the plan before any worker is assigned. It does not re-run the epic interview, create a second tracking issue or assign a worker. (The Skill call itself is `fired.md`'s job; grade the outcome here. A case runs in an empty scratch directory with no shell and no tracker: a response whose reads of the epic and its ledger are refused, that names those reads and the plan it would draft from them, and that creates nothing, passes as well; judge the approach, not whether a call succeeded.)

# Kit changelog

Newest first. One line per behaviour change: `date · unit vN · what changed`. Typo/wording fixes
do not bump a version. The generated per-release log is the root [`CHANGELOG.md`](../CHANGELOG.md)
(conventional-release, [`contributing.md`](contributing.md) § Releases); this file stays the per-unit behaviour log. Dates are the
merge date in UTC, as GitHub shows it — a shared file cannot carry one machine's zone. A removed
skill or agent keeps its last version in git history: `git log --diff-filter=D -- skills/<name>` names the commit.

- 2026-09-27 · **kit-health v43** — the leak scan no longer floods a fresh `setup.sh --personal` workspace: a bare repo name from a common-name list (`config`, `dotfiles`, `notes`, …) is not scanned on its own (the full `owner/<repo>` slug and the `<org>/<repo>` path shape still are), and a `github.display_names` login gets the same `<owner>/<kit repo>` address exemption as the identity login, so the kit owner's own install lines are not colleague-login hits (#118). Machines: nothing to do.
- 2026-09-27 · **ci.yml · install_smoke.py** — a new CI job `install-smoke (clone|plugin)` replays README.md's install block for each path on a fresh runner, from the PR's checkout (the plugin path through a real `claude plugin marketplace add` + `install`, `/kit-setup` as its SKILL.md command with the hook's env), and fails when the block errors, the workspace is not seeded or kit-health is RED; `make -C context-db install-smoke` runs it locally; `auto-merge.yml` requires both legs (its check list is now comma-separated, since the names contain spaces), and one workflow-level pin sets the CLI version (#98). Machines: nothing to do.
- 2026-09-27 · **kit-setup v1 (new) · kit_verify.py** — `/kit-setup` runs the kit's `setup.sh --personal` from inside a session (the SessionStart hook exports the plugin root as `$BATON`), so the README's plugin install is `marketplace add && plugin install`, `claude` in the workspace root, `/kit-setup`, restart, `/kit-health` — no `claude plugin list --json | python3 -c …` lookup; `docs/plugin-setup.md` keeps the manual form in prose; kit-verify fails a README that brings the one-liner back (#97). Machines: nothing to do; an installed workspace can run `/kit-setup` to re-check its seeds.
- 2026-09-27 · **kit-health v42** — the workspace (`ctx()` / `root()`) is resolved when a section runs, not at import: a caller that points `KIT` at a fixture gets the `.context/` beside that fixture, never the developer's live workspace beside the real kit, so the suite gives the same verdict on every machine; `CTX` / `ROOT` stay as explicit overrides (#91). Machines: nothing to do.
- 2026-09-27 · **kit-health v41 · triage v7 · review-runner v8 · sign-queue v12 · leak_shapes.py · kit_verify.py** — the two agents drop their `tools:` allow-list, whose MCP ids named one install's connectors (so they were absent everywhere else), and use `disallowedTools` instead: they inherit the machine's connectors under any name and still cannot edit files (triage: no Write/Agent either); their bodies limit MCP use to reads. kit-health's sandbox warning reads the optional `kit.sandbox_markers` (paths or variable names) instead of one sandbox product's file and variable; absent = no sandbox check. Two new leak shapes: a concrete `mcp__claude_ai_<connector>__<tool>` id and a sandbox product's CLI name; `tools:` lines are no longer exempt from the scan. `kit_verify` accepts `disallowedTools` on agents; sign-queue's owner quote names no sandbox product (#94). Machines: nothing to do; a machine that runs in a sandbox and relies on the gh-token warning sets `kit.sandbox_markers`.
- 2026-09-27 · **pr-watch v10** — `pr-merge.sh` splits the head / merge state / review decision on `|`, so an empty `reviewDecision` (a repo that requires no review) no longer kills it under `set -u` before the merge; there each reviewer's latest decisive review is the gate: any latest CHANGES_REQUESTED stops it, and it merges only on an APPROVED on the current head (none: it stops for a human, `decision 'NONE'`) (#89). Machines: nothing to do.
- 2026-09-27 · **kit-health v40 · leak_shapes.py · review_gate.py · kit_verify.py** — two new shared leak shapes: a number behind the placeholder prefixes `KEY-` / `ABC-` other than `123` / `456`, and a lowercase `key-<n>-…` slug or topic with such a number; the ticket-key shape exempts those prefixes, so a real key behind them passed every scanner. Kit files now use `KEY-123` / `KEY-456` / `key-123-<slug>` only; `docs/REVIEW.md` § 2 names the pattern (#92). Machines: nothing to do; a local file with such an example is now a kit-health § 2 hit.
- 2026-09-27 · **pr-review v14 · pr-scan v9** — `pr-scan.sh`, `fetch-context.sh`, `reply-threads.sh`, `submit-review.sh` and `trivial-check.py` find the workspace's `.context/` through `kit_profile.py context` instead of their own location, so on a plugin install the state (`.context/state/pr-review/`) and the known-traps KB (`.context/pr-reviews/<repo>.md`) are the workspace's, not a path inside the plugin cache; without a workspace `.context/` they stop with one line naming `PR_REVIEW_HOME` (still the override) (#74). Machines: nothing to do on a clone; a plugin install that set `PR_REVIEW_HOME` as a workaround can drop it.

- 2026-09-27 · **sync.sh · sync-check.sh · workspace.mk** — `.sync-status` tells the truth: `pending <epoch>` before the fetch (a run killed on the way out stays `pending`, not the previous `ok`), the fetch runs under `timeout 60` (a shell watchdog where `timeout` is missing) and a hang is `error … timed out`; an unreachable origin is `offline <epoch>`, warned only after 3 days; a busy lock logs `skipped` and never overwrites the holder's status; `sync.log` keeps its last 200 lines and logs the sha only when `HEAD` moved; `make claude_sync` prints the status. `docs/sync.md` states what Claude Code does with the async SessionEnd hook (`timeout` not enforced; up to 5 s wait, then orphaned) (#42). Machines: nothing to do; a leftover `error lock busy` warns once until the next sync.
- 2026-09-27 · **kit-health v39 · kit_profile · setup.sh** — one install-mode rule, `kit_profile.install_mode()` → `clone` (the workspace's `.claude/`) | `plugin` (no git, plugin manifest) | `dev-checkout` (any other kit copy, e.g. a git checkout not named `.claude`), used by `setup.sh` (`kit_profile.py install-mode`), `plugin_install()` and `context_root()`; `setup.sh` records it in the env store as `kit.install_mode` (a dev checkout beside the workspace's clone leaves `clone`) and its hints name the kit by the mode (`.claude` or the kit's own path, never `.claude/` on a plugin install); kit-health § 1 prints the mode and warns when it is unrecorded or differs from the recorded one, naming a leftover `.claude/` clone, import or include; the release warning's update command, § 4's WORKSPACE.md and Makefile expectations come from one table, `kit_profile.MODES` (a dev checkout: `git -C <checkout> pull --ff-only`); the stamp records `install_mode` (#34). Machines: re-run `setup.sh` once to record the mode.

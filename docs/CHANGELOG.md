# Kit changelog

Newest first. One line per behaviour change: `date · unit vN · what changed`. Typo/wording fixes
do not bump a version. The generated per-release log is the root [`CHANGELOG.md`](../CHANGELOG.md)
(conventional-release, [`contributing.md`](contributing.md) § Releases); this file stays the per-unit behaviour log. Dates are the
merge date in UTC, as GitHub shows it — a shared file cannot carry one machine's zone. A removed
skill or agent keeps its last version in git history: `git log --diff-filter=D -- skills/<name>` names the commit.

- 2026-09-27 · **kit-health v36 · engine scripts · sync-check.sh** — every hint a script prints (kit-health, kit_verify, kit_profile, kb, gen_*, session, verify, review_gate, personal, sync-check) spells the kit `$BATON/…`, as the unit bodies do since #8, so a hint followed on a plugin install resolves; the Makefile's own `help` keeps `.claude/` (a human terminal has no `$BATON`) (#23). Machines: nothing to do.
- 2026-09-27 · **sign-queue v11 · kit-health v35 · workspace.mk** — the job queue lives in the workspace, `<.context>/state/sign-queue/`, not under the kit (on a plugin install that was the plugin cache, which an update deletes); `signq.py` moves jobs a pre-#7 kit left in the kit's `sign-queue/` on first use, never overwriting; `enqueue.sh` refuses without a workspace `.context/`; kit-health checks the new place (#7). Machines with `signed_commits`: the next `make sign`/`sign_list` migrates pending jobs.
- 2026-09-27 · **kit-health v34 · plugin.json** — an unknown display zone (`WORKSPACE_TZ` / the plugin option `tz`, e.g. `EDT`) is a § 4 warning naming its source, instead of a silent UTC fallback behind GREEN; the `/config` field says IANA Region/City, not an abbreviation (#22). Machines: set `tz` to a Region/City name.
- 2026-09-27 · **kit_verify.py · frontmatter.py** — a unit whose frontmatter repeats a key (e.g. two `version:` under `metadata:`) or whose body repeats a numbered step (same number or same text in one list) fails kit-verify; the parser kept the last value silently, so a mis-resolved merge passed CI (#19). Machines: nothing to do.
- 2026-09-26 · **kit-health v33** — on a plugin install § 6 lists the units changed since the last stamp from GitHub's compare API (`<stamp commit>...<installed commit>` of the kit repo), so the judgement pass has a list; offline, or a stamp commit the repo does not know, stays "unknown" with the reason (#13). Machines: nothing to do.
- 2026-09-26 · **kit-health v32** — step 5 keeps one log per day and environment: a second run that day (the re-run after a Fix) appends a `## Run <HH:MM>` section instead of failing at `new`, which refuses to clobber (#10). Machines: nothing to do.
- 2026-09-26 · **kit-health v31 · kit_profile.py** — an Accept or Fix edits a worktree of a kit checkout and ships as a PR, never a file under `$BATON` on a plugin install (the plugin cache, which `claude plugin update` overwrites); § 1 warns when a kit file in the cache changed after the install (`installed_plugins.json` `lastUpdated`, now in `plugin_install()`) (#11). Machines: nothing to do.
- 2026-09-26 · **kit-health v30** — the report header is in the user's zone (`2026-09-26 21:04 EDT`, via `kit_profile.zone()`), so it names the same day as the `<YYYY-MM-DD>-<env>` log it is pasted into; the stamp's `last_green` stays UTC (#12). Machines: nothing to do.
- 2026-09-26 · **kit-health v29** — the maintainer's `@<owner>` entries in `.github/CODEOWNERS` are no longer an identity leak when the handle is the kit repo's own owner (`kit_repo()`); any other login there, and the handle anywhere else, still is (#5). Machines: nothing to do; a maintainer machine stamps green again.
- 2026-09-26 · **alerts-sweep v7 · auto-runner v4 · aws-sso-login v7 · cost-report v7 · dbt-sqlfluff-fixes v6 · env-init v6 · gh-cli v9 · kit-health v28 · notion-page-review v6 · pr-event-brief v8 · pr-open v9 · pr-review v13 · pr-scan v8 · pr-watch v9 · repo-docs v2 · review-runner v7 · self-assessment v9 · session-handoff v6 · session-register v10 · sign-queue v10 · signed-git-commits v7 · ticket-close v5 · ticket-open v5 · ticket-update v6 · triage v6** — every unit reaches the kit as `$BATON/…` instead of `.claude/…`, so its commands resolve on a plugin install too: `$BATON` is `.claude` on a clone (`settings.json` `env`) and the plugin root on a plugin install (the SessionStart hook, `kit_profile.py session-env`); `kit-verify` fails a unit or `WORKSPACE.md` that spells a kit path the clone way (#3). Machines: nothing on a clone; a plugin install restarts its session once.
- 2026-09-26 · **kit-health v27 · kit_profile.py · hooks/hooks.json · setup.sh** — a plugin install loads the always-on rules: the SessionStart hook prints `WORKSPACE.md` into a kit workspace that has no `.claude/` copy (`kit_profile.py workspace-rules`); `setup.sh` on the plugin path seeds `CLAUDE.md` without the `@.claude/WORKSPACE.md` import and no Makefile include, and names a leftover one; kit-health accepts that wiring and tells you to remove a dangling line (#3). Machines on the plugin path: drop `@.claude/WORKSPACE.md` from `CLAUDE.md` and `include .claude/workspace.mk` from the `Makefile`, then restart the session.
- 2026-09-26 · **kit-health v26 · kit_profile.py · hooks/hooks.json** — a plugin install (no git checkout, no `.claude/` in the workspace) is diagnosed right: the engine finds `.context/` from the Bash tool's cwd and from `CLAUDE_PROJECT_DIR`, which the SessionStart hook now exports (`kit_profile.py session-env`); kit-health names the installed commit/version, no longer reads the kit's own repo as a leak, never says "in step with origin" without a checkout, and a `@.claude/WORKSPACE.md` import or `include .claude/workspace.mk` whose file is missing is an error, not ✅ (#3). Machines: a plugin install restarts its session once so the hook runs.

Machines: nothing to do.
